## Key Question 1: What are the exact problems reported, with their multi-part progression? (Problem catalog)

### Takeaway
Across all sources there are roughly 20 distinct exercises attributed to Sierra, of which five are corroborated by two or more independent first-hand accounts: (1) the multi-part "flaky API → resolve product IDs → compact conversation to a token limit" CoderPad screen, (2) spreadsheet circular-reference (cycle) detection, (3) the "find ~3–6 planted bugs in a small agent codebase using a flowchart/diagram and CLI output, explain customer impact" debugging round, (4) the take-home "build a customer-service agent for a fictional (outdoors) company with a provided OpenAI key, pick 2 of 5 features, then present and defend", and (5) retry/backoff-with-timeout on failing Python code. No source provides a full verbatim multi-part problem statement; the fullest reconstructions are below.

### Cited Findings

**P17. OFFICIAL AI-native onsite: Plan / Build / Review (all engineering roles incl. infrastructure; from 2026-04-22)**
- Post "The AI-native interview" by Vijay Iyengar, Arya Asemanfar, Angie Wang, 2026-04-22. Old loop: "two coding interviews, plus interviews for algorithms, system design, and culture fit, followed by reference checks." Change: "We removed our coding and algorithms interviews and replaced them with an AI-native onsite." Phone screen: the coding phone screen (which "required writing code without AI in an online editor") replaced with a system design interview, reasoning that vibe-coding an app is easy but "getting it into production in a scalable way" is the harder problem. Plan: candidate drives ideation of a product in their own domain while interviewers ask questions to strengthen it. Build: interviewer leaves; "2 hours, using the AI tooling and frameworks of their choice"; "complete freedom to pivot or adjust scope"; guidance shared in advance: "OK to cut your scope as you build, and to skip boilerplate (CRUD, auth) to focus on what's unique" (cites Paul Buchheit's "if it's great, it doesn't have to be good"). Review: demo; discuss product flows/choices; "review the code to understand their technical judgment" (data model, abstractions, extensibility); path to production; "We also dig into how they used AI along the way." Evaluation "agnostic to what the candidate builds"; interviews run in pairs; "hiring for strengths, not just an absence of weakness." Example builds: a trivia enthusiast built "an AI-powered game meant to keep the user in a state of flow" (demo = interviewer playing it); a backend engineer built "a headless simulation tool and used an agent guided by a markdown file to walk through the demo." Debugging pilot: "a medium-sized codebase and a draft PR from a colleague that introduces a cross-cutting feature"; review and improve it using coding agents; "the level of AI used in this interview is still TBD." ## Key Question 4: How do Agent Engineer / Forward Deployed Engineer loops differ from core Software Engineer loops?

### Takeaway
Agent Engineer loops (2025–2026) are: recruiter → 60-min DS screen → take-home customer-service agent (OpenAI key, pick 2 of 5 features, metrics/observability write-up) → onsite of TS/React or agent-codebase debugging + take-home presentation + teach-a-topic + hiring-manager values round. FDE loops swap coding for a metric-diagnosis take-home and north-star-metric design. Core SWE loops (pre-April-2026) had two coding + algorithms + system design; post-April-2026 they are system-design screen + Plan/Build/Review.

### Cited Findings
- Agent Engineer loop detail (first-hand): recruiter 60 min → LeetCode-style screen (Excel cycle) → take-home (outdoors company) → onsite: debugging (TS/React), take-home review + 5–10 min teach-a-topic, hiring manager ("Walk me through your resume and why you made each move", "time you worked with stakeholders", "project you're most proud of"); "expect every interviewer to be an agent engineer." — [Aced experience 8549fc](https://www.aced.io/experiences/sierra-ai-machine-learning-engineer-interview-8549fc)
- Software Engineer, Agent loop (first-hand): recruiter 30 min → CoderPad multi-part practical → CoderPad debugging (agent codebase + diagram) → take-home agent + 60-min presentation → 60-min hiring manager on "agency and collaboration: ownership, driving projects, handling disagreements, working across teams"; "This isn't a generic 'tell me about a time' round." — [Gaijineer](https://gaijineer.co/sierra-software-engineer-agent-interview-experience)

## Key Question 6 (synthesis): Recurring problems, recurring families, and the 2023 → 2026 shift

### Takeaway
Problem families cluster around the agent-engineering job itself: retry/backoff against flaky APIs, resolving product/catalog graphs, token-budget compaction, Markdown chunking, interval/stream processing, graph cycle detection, planted-bug debugging of agent code, and "build a customer-service agent for a fictional company." The loop moved from LeetCode-style single questions (2024–early 2025) to multi-part practical screens (2025) to an AI-tools-expected build onsite (April 2026), while new-grad/agent screens still forbid AI in late 2026.

### Cited Findings (recurrence table; sources listed in KQ1)
- Reported by 2+ independent first-hand sources: P1/P1b flaky-API → product-ID → compaction family (Gaijineer; 1point3acres 1192645; 1point3acres 1193376; Aced 7216); P2 spreadsheet cycle detection (Aced 8549fc; Aced 5875 "2 interviews"; 1point3acres reply); P6 agent-codebase debugging with diagram/CLI output (Aced 67fe22; Gaijineer; 1point3acres 1175298); P8 fictional-company agent take-home (Aced 8549fc; Gaijineer; Aced question bank mid-2026).
- Single first-hand source: P3 grid word search; P4 retry/backoff (APX); P5 catalog traversal (APX); P7 TS/React debugging (Aced 8549fc; generalized by aggregators); P9 FDE metric diagnosis; P10 Markdown chunking; P11 "Debug View" intervals; P12 stream merging; P13 new-grad OA; P14 pub/sub chat onsite.
- Aggregator-only / unattributed: P15 keyboard undo/redo; subscription-cancellation agent design; "wrap an API in retries and rate limiting" (techinterview.org).
- Explicitly speculative: interviewsense (anagrams, sliding window, merge intervals, rate limiter, notification fan-out); GitHub sierra.md 13 representative questions; PracHub refund-status case.
- Timeline anchors: Agent Engineer role publicly defined 2024-07-11 — [Sierra blog](https://sierra.ai/blog/meet-the-ai-agent-engineer); LeetCode-style Agent Engineer screen in Apr 2025 — [Aced 8549fc](https://www.aced.io/experiences/sierra-ai-machine-learning-engineer-interview-8549fc); "Debug View" OA Oct–Dec 2025 — [1point3acres 1155857](https://www.1point3acres.com/interview/thread/1155857); stream-merge screen Jan–Mar 2026 — [1point3acres 1165332](https://www.1point3acres.com/interview/thread/1165332); Markdown chunking screen Apr–Jun 2026 — [1point3acres 1176834](https://www.1point3acres.com/interview/thread/1176834); official removal of coding/algorithms 2026-04-22 — [Sierra blog](https://sierra.ai/blog/the-ai-native-interview); SWE onsite with "AI coding exercises" Jul–Sep 2026 — [1point3acres 1192971](https://www.1point3acres.com/interview/thread/1192971); New Grad no-AI phone screen and OA with TypeScript AI project Oct–Dec 2026 — [1point3acres 1193376](https://www.1point3acres.com/interview/thread/1193376), [1192604](https://www.1point3acres.com/interview/thread/1192604).

### Inferences
- Family map for practice: (a) retry/backoff/timeout wrapper → P1 part 1, P4, techinterview.org; (b) product/catalog graph resolution with fallback IDs → P1 part 2, P5; (c) conversation/token compaction → P1b, Aced 7216, 1193376; (d) RAG-style text chunking → P10; (e) intervals/overlaps/gaps and stream merging → P11, P12; (f) graph cycle detection / 2D grid DFS → P2, P3; (g) planted-bug debugging of a 4–5-file agent or a TS/React app with customer-impact narration → P6, P7, official PR pilot; (h) build-an-agent with tool calling for a fictional company plus metrics/observability → P8; (i) agent metric diagnosis & north-star metrics (FDE) → P9; (j) pub/sub customer-service chat system (system design) → P14, P16 Spotify prompts. Families named in the assignment but with no Sierra attribution found: rate limiter (only speculative interviewsense), LRU/TTL cache, versioned KV store, log parsing, file system simulation, bank/ledger, scheduler, tokenizer, text diff, streaming JSON parsing.
- The shift: 2023–2024 is undocumented in any accessible source; the earliest dated first-hand report is Apr 2025 (single-DS-question screen + TS/React debugging). Through 2025 the Agent SWE track used practical multi-part CoderPad screens. From 2026-04-22 Sierra's core engineering track dropped coding/algorithms for a system-design screen and a 2-hour AI-assisted build. Late-2026 reports show practical coding (API/pagination/compaction, 45-min pair programming, OAs) persisting on new-grad and agent tracks with AI disallowed, so the official change should be read as applying to the core experienced-SWE onsite, with per-track variation.
- Direction of travel is toward evaluating AI-tool judgment (Review stage "how they used AI"; PR-review-with-agents pilot), and toward LLM-adjacent data plumbing in screens rather than classic algorithms.

### Gaps
- No first-hand account from 2023 or 2024 was found; the "two coding + algorithms" old loop is known only from Sierra's own description.
- Multiple-attribution counts depend on Aced's "N interviews reported" tags and 1point3acres teasers whose bodies are hidden; exact wording and follow-ups for P10–P14 remain unverified.
- Glassdoor's individual reviews (reported in search summaries as mentioning "a standard DSA LC question") could not be read, so any additional distinct problems there are missing from this catalog.
